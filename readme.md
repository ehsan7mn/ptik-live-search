# جستجوی زنده (PTik Live Search)

نسخه: 1.4.0
نویسنده: امیراحسان مهدیزاده — [persiantik.net](https://persiantik.net)

جستجوی زنده (AJAX) بین نوشته‌ها، برگه‌ها، محصولات و تاکسونومی‌های سایت، با نمایش نتایج به‌صورت گروه‌بندی‌شده بر اساس نوع محتوا.

## استایل‌های شورتکد (attribute جدید `style`)

با مشخصه‌ی `style` می‌توان ظاهر کادر جست‌وجو را عوض کرد:

```
[ptik_search source="product" style="glass1"]
```

| مقدار `style` | توضیح |
|---|---|
| `default` | بدون کلاس/استایل اضافه؛ کاملاً به CSS خود قالب وابسته است (رفتار نسخه‌های قبل از ۱.۲.۰). |
| `glass1` | کادر شیشه‌ای (glassmorphism، پس‌زمینه‌ی نیمه‌شفاف با `backdrop-filter: blur`) به‌همراه آیکون دو چشم بیضی که هر چند ثانیه به اطراف نگاه می‌کنند. |
| `solid-primary` | کادر توپر با رنگ `var(--primary)` (اگر قالب نداشته باشد، آبی پیش‌فرض)، دکمه‌ی گرد سفید با آیکون ذره‌بین. |
| `outline-primary` | نسخه‌ی معکوس `solid-primary`: کادر سفید با بوردر `var(--gray1)`، دکمه‌ی گرد با رنگ `var(--primary)`. |
| `gradient-spin` | حلقه‌ی گرادیانت آبی-بنفش که پیوسته دور کادر می‌چرخد؛ پس‌زمینه‌ی داخل کادر کاملاً شفاف است. |
| `shine-border` | کپی دقیق افکت «شاین بوردر» سایت app.leonardo.ai؛ دو نور محو که دور بوردر می‌چرخند. از ویژگی‌های نسبتاً جدید CSS (`mask`, `offset-path`, `mix-blend-mode`) استفاده می‌کند؛ روی مرورگرهای مدرن (Chrome/Edge/Safari اخیر) تست شود. |
| `minoru` | افکت فوکوس از دموی tympanus.net: با فوکوس روی اینپوت، یک حلقه از دور کادر باز و محو می‌شود (افکت ضربان). |
| `madoka` | افکت فوکوس از دموی tympanus.net: با فوکوس روی اینپوت، یک بوردر SVG دور کادر «کشیده می‌شود». |

## تغییر مهم نسخه ۱.۱.۳

- نام شورتکد از `asearch` به `ptik_search` تغییر کرد؛ در محتوای قدیمی باید دستی جایگزین شود.
- بررسی nonce از AJAX حذف شد چون در سایت‌هایی با کش صفحه (page cache) باعث می‌شد کاربران مهمان با «محتوایی یافت نشد» مواجه شوند (نتایج فقط برای ادمین کار می‌کرد). این endpoint فقط داده‌ی عمومی و منتشرشده را می‌خواند، پس ریسک امنیتی خاصی از این بابت وجود ندارد.

## نصب

پوشه‌ی `ptik-live-search` را داخل `wp-content/plugins/` قرار بده و از پنل وردپرس فعالش کن.

## استفاده

```
[ptik_search source="product,post,page" taxonomy="product_cat,category" image="true" price="true" count="8" depth="2" absolute="true"]
```

## مشخصه‌های شورتکد

| مشخصه | مقدار پیش‌فرض | توضیح |
|---|---|---|
| `source` | خالی (اگر هم `source` و هم `taxonomy` خالی باشند، پیش‌فرض `product` می‌شود) | لیست پست‌تایپ‌ها برای جست‌وجو، با کاما جدا شود؛ مثل `product,post,page`. هر پست‌تایپ یک گروه جدا با تیتر مخصوص به خودش در نتایج می‌سازد. |
| `taxonomy` | خالی | لیست تاکسونومی‌ها برای جست‌وجو در نام ترم‌ها، با کاما جدا شود؛ مثل `product_cat,category`. هر تاکسونومی هم یک گروه جدا با تیتر مخصوص به خودش می‌سازد. |
| `image` | `true` | نمایش تصویر شاخص/بندانگشتی کنار هر نتیجه. اگر تصویری موجود نباشد، تصویر جایگزین ۶۰×۶۰ ووکامرس نمایش داده می‌شود. |
| `price` | `false` | فقط برای گروه محصول: نمایش قیمت (`get_price_html`) کنار هر نتیجه، در صورت فعال بودن ووکامرس. |
| `placeholder` | `کد یا نام محصول را وارد کنید` | متن placeholder فیلد جست‌وجو. |
| `count` | `5` | تعداد نتایج نمایشی در هر گروه (چه پست‌تایپ چه تاکسونومی). |
| `depth` | `0` (بدون محدودیت) | فقط برای تاکسونومی‌های سلسله‌مراتبی (مثل `product_cat`): محدود کردن نتایج به چند سطح. مثلاً `depth="1"` فقط دسته‌های سطح اول (بدون والد) را می‌آورد، `depth="2"` دسته‌های سطح اول و زیردسته‌های یک لایه پایین‌تر را، و به همین ترتیب. |
| `absolute` | `false` | اگر `true` باشد، باکس نتایج به‌صورت `position: absolute` روی محتوای زیرش نمایش داده می‌شود (کلاس‌های بوت‌استرپی `position-relative` روی wrapper و `position-absolute w-100` روی باکس نتایج اضافه می‌شود) تا هنگام نمایش نتایج، اسکرول صفحه جابه‌جا نشود. مناسب حالتی که کادر سرچ وسط صفحه است. |
| `style` | `default` | ظاهر کادر سرچ. مقادیر ممکن: `default`, `glass1`, `solid-primary`, `outline-primary`, `gradient-spin`, `shine-border`, `minoru`, `madoka` (توضیح هرکدام در بخش «استایل‌های شورتکد» پایین‌تر). |

## تنظیمات پلاگین

از منوی «جستجوی زنده» در دسترس است:

- اگر افزونه‌ی مدیریتی `persiantik_shop_themes` یا `persiantik_themes` روی سایت فعال باشد، منو زیرمجموعه‌ی همان افزونه نمایش داده می‌شود (اولویت با `persiantik_shop_themes`).
- در غیر این صورت، به‌صورت یک منوی مستقل درست بالای «تنظیمات» در سایدبار ادمین نشان داده می‌شود.

- **دکمه «نتایج بیشتر»**: نمایش/عدم‌نمایش دکمه‌ای در انتهای نتایج که به صفحه جست‌وجوی عادی وردپرس با همان کلمه لینک می‌دهد.

## نمایش شمارش در نتایج تاکسونومی

به‌جای قیمت، سمت راست هر نتیجه‌ی تاکسونومی یک شمارش نمایش داده می‌شود:

- برای تاکسونومی‌های مرتبط با محصول (مثل `product_cat`): `X محصول`
- برای تاکسونومی‌های عادی (دسته‌بندی/برچسب نوشته و ...): `X نوشته`
- برای تاکسونومی‌هایی که فقط به برگه تعلق دارند: چیزی نمایش داده نمی‌شود

- https://app.leonardo.ai/ — افکت "shine border" (حلقه‌ی نورانی چرخان دور کادر جست‌وجو)

## بروزرسانی خودکار از گیت‌هاب (بدون آپلود دستی روی هر سایت)

این پلاگین آماده‌ی اتصال به کتابخونه‌ی رایگان [Plugin Update Checker](https://github.com/YahnisElsts/plugin-update-checker) است تا وردپرس هر سایتی که این پلاگین رویش نصب است، خودش نسخه‌ی جدید را از گیت‌هاب تشخیص بدهد و پیغام «بروزرسانی موجود است» نشان دهد.

### مراحل یک‌بار برای راه‌اندازی

1. از لینک بالا، آخرین نسخه‌ی کتابخونه را دانلود کن (دکمه‌ی سبز Code → Download ZIP، یا از بخش Releases خود ریپو).
2. فایل‌های استخراج‌شده را در مسیر `ptik-live-search/vendor/plugin-update-checker/` این پلاگین قرار بده (باید فایل `plugin-update-checker.php` مستقیم داخل همین پوشه باشد).
3. یک ریپازیتوری **private** روی گیت‌هاب برای این پلاگین بساز (اگر هنوز نساختی) و کل پوشه‌ی `ptik-live-search` را داخلش push کن.
4. آدرس ریپازیتوری از قبل با یوزرنیم گیت‌هاب `ehsan7mn` تنظیم شده:
   ```php
   'https://github.com/ehsan7mn/ptik-live-search/',
   ```
   فقط اگر اسم ریپو رو چیز دیگه‌ای غیر از `ptik-live-search` گذاشتی، همین خط رو تو `ptik-live-search.php` باید دستی هماهنگ کنی.
5. چون ریپازیتوری خصوصی است، باید یک **Personal Access Token** بسازی: گیت‌هاب → عکس پروفایل → Settings → Developer settings → Personal access tokens → Generate new token (دسترسی `repo` کافیست).
6. توکن را داخل خود پلاگین ننویس؛ به‌جایش داخل فایل `wp-config.php` هر سایت (بالای خط `/* That's all, stop editing! */`) این خط را اضافه کن:
   ```php
   define( 'PTIK_GITHUB_TOKEN', 'ghp_xxxxxxxxxxxxxxxxxxxx' );
   ```

### مراحل تکراری برای هر نسخه‌ی جدید

1. فایل‌های جدید پلاگین را جایگزین نسخه‌ی قبلی در پوشه‌ی محلی ریپازیتوری کن.
2. شماره‌ی `Version` در هدر `ptik-live-search.php` را بالا ببر.
3. با GitHub Desktop: Commit → Push.
4. یک **Release** جدید روی گیت‌هاب بزن با Tag مطابق همون ورژن (مثلاً `v1.2.1`) — از تب Releases خود ریپو، دکمه‌ی «Draft a new release».
5. تمام. هر سایتی که این پلاگین رویش نصب است، طی چند ساعت (یا با زدن دکمه‌ی «Check for updates» در پنل پلاگین‌ها) بروزرسانی را می‌بیند و با یک کلیک نصبش می‌کند — دیگر نیازی به آپلود دستی روی تک‌تک سایت‌ها نیست.

> نکته: همین روش را می‌توانی برای هر پلاگین سفارشی دیگری هم تکرار کنی — هرکدام فقط به ریپازیتوری گیت‌هاب و همین چند خط کد نیاز دارند.

## رفع باگ مهم نسخه ۱.۲.۲

تا قبل از این نسخه، استایل‌شیت و اسکریپت پلاگین از **داخل تابع شورتکد** لود می‌شدند (`wp_enqueue_style`/`wp_enqueue_script` داخل `ptik_search_func`). این اشتباه فنی باعث می‌شد که چون شورتکد معمولاً دیرتر از `wp_head` اجرا می‌شود، فایل CSS اصلاً به صفحه اضافه نشود — در نتیجه هیچ‌کدام از استایل‌های `style` درست نمایش داده نمی‌شدند (نه فقط `madoka`، همه). از نسخه‌ی ۱.۲.۲ به بعد، لود فایل‌ها روی هوک درست `wp_enqueue_scripts` انجام می‌شود.

اگر قبلاً یکی از نسخه‌های ۱.۱.x یا ۱.۲.0/۱.۲.۱ را نصب کرده بودید و استایل‌ها بی‌اثر به نظر می‌رسیدند، علتش همین بوده — با آپدیت به ۱.۲.۲ برطرف می‌شود.

## رفع باگ نسخه ۱.۲.۳ (فقط استایل madoka)

`.ptik-input-wrap--madoka` یک `<span>` بود که هیچ `display` صریحی نداشت، پس به‌صورت `inline` می‌ماند و اندازه‌اش با محتوا جمع می‌شد (نه با عرض واقعی اینپوت) — همین باعث می‌شد بوردر SVG و لیبل کاملاً نامرتب و اندازه‌غلط نمایش داده شوند. `display: block` اضافه شد. همچنین چند ویژگی پایه‌ای اینپوت (`border: none`, `outline: none`, `-webkit-appearance: none` و ...) که در دموی اصلی از یک کلاس مشترک می‌آمد و در تبدیل به این پلاگین جا افتاده بود، مستقیماً به `.ptik-input--madoka` اضافه شد.

## رفع باگ نسخه ۱.۲.۴ (فقط استایل madoka)

`.ptik-label--madoka` روی `position: absolute` بود ولی `top`/`left` نداشت — طبق قوانین CSS، وقتی این‌طوریه، عنصر به‌جای اینکه دقیقاً روی اینپوت بشینه، می‌ره سر جای «طبیعی»‌اش تو جریان صفحه (یعنی درست زیر اینپوت، نه روش). با اضافه‌شدن `top:0; left:0;` این مشکل حل شد. همچنین SVG قاب دور کادر هم صریحاً `position:absolute` و اندازه‌ی کامل گرفت تا مستقل از رفتار پیش‌فرض چیدمان درست روی کادر بشینه.

## رفع باگ واقعی نسخه ۱.۲.۴ (مخصوص madoka — این‌بار درست)

مقایسه مستقیم با فایل CSS اصلی دمو (`tympanus.net/Development/TextInputEffects/css/set1.css`) نشان داد کلاس‌های پایه‌ای (`.graphic { fill: none }` و مشابه) که در تبدیل اولیه به این پلاگین جا افتاده بودند، باعث باگ می‌شدند:

- مسیر SVG (`<path>`) هیچ‌وقت `fill: none` نگرفته بود — پیش‌فرض SVG برای فیل‌نشده «مشکی توپر» است، برای همین به‌جای یک بوردر خالی، یک مستطیل کاملاً مشکی نمایش داده می‌شد.
- `background` در چند لایه (خود `.search_bar`، wrapper، اینپوت) به‌صورت صریح و با `!important` روی `none` قفل شد تا هیچ CSS دیگری از قالب (که برای طراحی قدیمی‌تر نوشته شده) رویش اثر نگذارد.

## نسخه ۱.۲.۵ (اصلاحات madoka)

- بوردر ضخیم‌تر در چپ/راست نسبت به بالا/پایین رفع شد: چون `preserveAspectRatio="none"` باعث می‌شد viewBox باریک (404×77) با نسبت خیلی متفاوتی نسبت به کادر واقعی (خیلی پهن) کشیده شود، ضخامت بوردر در جهت افقی و عمودی متفاوت می‌شد. با افزودن `vector-effect="non-scaling-stroke"` روی مسیر SVG، ضخامت بوردر همه‌جا یکسان و نازک شد.
- به‌جای متنِ در حال کوچک‌وجابه‌جاشدن «جستجو»، حالا یک آیکون ذره‌بین ثابت (بدون انیمیشن، بدون افتادن به پایین موقع فوکوس) سمت چپ کادر نمایش داده می‌شود.
- رنگ متن تایپ‌شده در اینپوت از `var(--primary)` به `var(--text)` تغییر کرد.

## نسخه ۱.۲.۶ (اصلاح مکانیزم trigger افکت madoka)

قبلاً افکت madoka هم با `:focus` (CSS) و هم با کلاس `is-filled` (جاوااسکریپت) هم‌زمان فعال می‌شد. طبق خواسته‌ی صریح، حالت `:focus` کاملاً حذف شد — افکت **فقط** با اسکریپت (`ptik-search.js`، دقیقاً معادل اسکریپت اصلی دموی tympanus.net با رویدادهای `focus`/`blur` روی خود اینپوت که کلاس `is-filled` را روی wrapper اضافه/حذف می‌کند) فعال می‌شود. همچنین چند خاصیت ساختاری که از کلاس‌های پایه‌ی دموی اصلی (`.input`, `.input__field`) جا افتاده بود (`z-index: 1`, `float: right`) برای هم‌خوانی بیشتر با مرجع اضافه شد.

## رفع باگ نسخه ۱.۲.۷ (اصلاح دو اشتباهی که در ۱.۲.۵ و ۱.۲.۶ وارد شده بود)

استایل madoka از نسخه ۱.۲.۵ به بعد اصلاً بوردر نشان نمی‌داد. علت، دو تغییری بود که خودِ نسخه‌های قبلی وارد کرده بودند:

1. **`float: right` روی اینپوت (وارد شده در ۱.۲.۶):** باعث می‌شد wrapper ارتفاعش صفر شود. چون SVG بوردر `position:absolute; height:100%` است، ۱۰۰٪ از صفر هم صفر می‌شد و هیچ بوردری رسم نمی‌شد — و متن پاراگراف بعدی هم به اینپوت می‌چسبید. این ویژگی از `.ptik-input--madoka` و `.ptik-input--minoru` حذف شد.
2. **`vector-effect: non-scaling-stroke` (وارد شده در ۱.۲.۵):** ضخامت بوردر را یکسان می‌کرد ولی طول `stroke-dasharray` را هم به پیکسل صفحه تبدیل می‌کرد؛ چون محیط واقعی کادر خیلی بزرگ‌تر از ۹۶۲ بود، مستطیل هیچ‌وقت کامل بسته نمی‌شد. حذف شد.

به‌جای آن‌ها، حالا اسکریپت `ptik-search.js` مقدار `viewBox` را با ابعاد واقعی کادر هم‌اندازه می‌کند (و `pathLength="962"` می‌گذارد). این‌طور هیچ کششی رخ نمی‌دهد، ضخامت بوردر همه‌جا یکنواخت می‌ماند و انیمیشن کشیده‌شدن بوردر دقیقاً مثل دموی اصلی کامل بسته می‌شود. با تغییر اندازه‌ی پنجره هم دوباره هم‌اندازه می‌شود.

## نسخه ۱.۲.۸ — حالت استراحت madoka دقیقاً مثل دمو

در دموی اصلی، کادر در حالت عادی فقط **یک خط افقی زیر اینپوت** دارد و با کلیک، بوردر کامل دور کادر کشیده می‌شود. مقادیر ثابت `stroke-dasharray: 962` / `stroke-dashoffset: 558` فقط برای ابعاد خاص دموی اصلی (۴۰۴×۷۷) درست بودند؛ روی یک کادر جست‌وجوی تمام‌عرض، خطِ حالت استراحت کوتاه‌تر از یک ضلع کامل می‌شد.

حالا این دو مقدار به‌صورت CSS custom property (`--ptik-madoka-perimeter` و `--ptik-madoka-rest`) تعریف شده‌اند و اسکریپت آن‌ها را از روی ابعاد واقعی کادر پر می‌کند: محیط واقعی مستطیل، و offsetی که دقیقاً یک ضلع افقی کامل نمایان بماند. با تغییر اندازه‌ی پنجره هم دوباره محاسبه می‌شود.

## نسخه ۱.۲.۹

- `.search_result`: افزودن `box-shadow: 0 0 20px rgba(0,0,0,.1)` و `z-index: 9999999` برای نمایش صحیح در حالت `absolute="true"`.
- `.search_result a`: رنگ `var(--text)` و در هاور `var(--primary)`.
- `.ptik-group-title`: افزودن `text-align: right`.
- استایل madoka: `font-weight` اینپوت از bold به `500` تغییر کرد؛ `max-width: 700px` و `margin: 1.1em auto` (وسط‌چین).
- استایل **minoru** بازنویسی شد: در حالت عادی بوردر `1px solid var(--gray1)` دارد و با کلیک، رینگ `var(--primary)` می‌گیرد و موج ضربانی (افکت اصلی دمو) با رنگ `var(--primary)` پخش می‌شود. موج از `z-index: -1` به `z-index: 0` منتقل شد، چون در قالب‌هایی که کانتینر پس‌زمینه‌ی سفید دارد، مقدار منفی باعث می‌شد موج پشت پس‌زمینه پنهان بماند و اصلاً دیده نشود. همچنین `position: relative` روی فرم اضافه شد تا لیبل مطلق نسبت به خود کادر جای بگیرد.

## نسخه ۱.۳.۰

- تمام `font-family`ها از CSS افزونه حذف شدند تا فونت هر استایل از خود قالب ارث ببرد و خراب نشود.
- استایل minoru: رنگ‌ها عیناً از دموی اصلی گرفته شد — بوردر و رینگ فوکوس `#eca29b` با ضخامت `2px`، و رنگ موج ضربانی `rgba(199,152,157,0.6)`. (قبلاً اشتباهاً `var(--primary)` گذاشته شده بود که خیلی پررنگ‌تر از دمو بود.)
- استایل minoru: آیکون ذره‌بین در سمت چپ کادر اضافه شد (جایگزین متن مخفی لیبل) و `max-width: 700px` با وسط‌چین شدن اعمال شد.

## نسخه ۱.۴.۰ — رفع باگ بحرانی سلکتورها و تأیید همه‌ی استایل‌ها

**باگ اصلی:** قوانین CSS شش استایل با نام کلاس‌هایی نوشته شده بود که شورتکد هیچ‌وقت تولید نمی‌کرد:

| CSS داشت | مارک‌آپ واقعاً تولید می‌کرد |
|---|---|
| `.ptik-search--glass1` | `.ptik-form--glass1` |
| `.ptik-search--solid` | `.ptik-form--solid-primary` |
| `.ptik-search--outline` | `.ptik-form--outline-primary` |
| `.ptik-search--gradient` | `.ptik-form--gradient-spin` |
| `.ptik-search--shine` | `.ptik-form--shine-border` |
| `.search_div` (کلاس قالب) | `.ptik-form--default` |

یعنی این شش استایل عملاً **هیچ CSS ای دریافت نمی‌کردند** — نه متغیر، نه پدینگ، نه گرادیانت، نه انیمیشن. همه اصلاح شدند.

**سایر تغییرات:**

- همه‌ی استایل‌ها: `max-width: 700px` و `margin: 20px auto` (وسط‌چین) و رنگ متن هماهنگ با قالب.
- `gradient-spin`: گوشه‌های گرد به‌خاطر کشیده‌شدن `viewBox` بیضی می‌شدند؛ حالا اسکریپت `viewBox`، گرادیانت و مستطیل‌های ماسک را با ابعاد واقعی کادر هم‌اندازه می‌کند (و با تغییر اندازه‌ی پنجره دوباره).
- `shine-border`: پس‌زمینه از مشکی به `transparent` تغییر کرد تا روی هر تمی قابل استفاده باشد؛ رنگ نور همان `#6e60ee` اصلی leonardo.ai باقی ماند.
- `glass1`: متن، placeholder و آیکون چشم‌ها سفید شدند؛ کادر SVG چشم‌ها از ۳۴×۱۸ به ۴۲×۲۲ بزرگ‌تر شد.
- `default`: `border-radius` از مقدار ثابت به `var(--radius1, 10px)` تغییر کرد.

**یادآوری نصب:** نام پوشه‌ی افزونه باید همیشه `ptik-live-search` باشد (بدون شماره‌ی نسخه). اگر پوشه به شکل `ptik-live-search-1.2.8` نصب شود، هر بروزرسانی مسیر فایل‌ها را عوض می‌کند و سیستم بروزرسانی خودکار گیت‌هاب هم درست کار نمی‌کند.
